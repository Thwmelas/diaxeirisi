# YOLO-Object detection
## Setup (Ubuntu / WSL)
A virtual environment is required, because Ubuntu 24.04 does not allow
installing Python packages system-wide with pip.

    sudo apt update
    sudo apt install python3-pip python3-venv
    python3 -m venv venv
    source venv/bin/activate
    pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
    pip install -r requirements.txt

Every time a new terminal is opened, activate the environment first:
  source venv/bin/activate

## Technical Dependencies & Framework
The object detection pipeline is developed and executed using the Ultralytics YOLOv8 framework(pip install ultralytics) running on PyTorch (Python 3.8+) and trained at an image resolution of imgsz=1024.

## Dataset Configuration & Class Balancing
For the training of our model, we utilized and adapted a custom dataset to ultimately include eight classes: car, heavy vehicles, light vehicles, buildings, person, tree, plane, and boat.

## Handling Class Imbalance
Initially, the dataset contained more classes (such as fire). However, due to severe class imbalance regarding the number of bounding boxes among the categories, we made the following modifications:

1.The fire class was completely removed, as its sparse data hindered smooth and stable training.

2.The boat and plane classes were retained despite having fewer samples. Our experimental trials revealed that the model achieves very high performance on these classes because they are easily distinguishable due to their characteristic background context.

3.To increase the volume of data for certain categories and achieve better balance against dominant classes (car and person), we merged similar categories. Specifically, buses and trucks were combined into the heavy vehicles class, while motorcycles and tricycles were grouped into the light vehicles class.


## Training Strategy & Fine-Tuning

The training of the model was conducted progressively through multiple experimental runs, with each cycle typically lasting 50 epochs. To optimize performance, we applied two methods:

1.Training the model on the data from scratch without prior knowledge, to assess its baseline behavior.

2.In many instances, saving the optimal checkpoint from a previous run (the best.pt file) and feeding it back into the model as a starting point for additional training cycles. This helped the model continuously improve its accuracy by leveraging pre-acquired knowledge.


## Evaluation & Performance Metrics

By applying the continuous fine-tuning strategy, we produced the final optimal model (best.pt). As demonstrated by the evaluation results, the model achieved an overall mAP50 accuracy of 65.3% (0.653), a Precision of 73.3% and a Recall of 61.7% across a total of 42,190 detected instances..
The initial hypothesis regarding high performance on classes with distinct environmental backgrounds was fully confirmed, as the model recorded exceptional performance on the planes (mAP50: 89.7%), car (mAP50: 85.4%), tree (mAP50: 81.7%), and boat (mAP50: 81.5%) classes. Conversely, classes featuring smaller or visually complex objects (such as light_vehicles and heavy_vehicle) performed at lower levels (mAP50 around 43%).

## Inference Speed: imgsz 640 vs 1024 

Each demo video was processed with both image sizes on the CPU. The values below are the average time per frame reported by python3 yolo_vision.py <video> [imgsz].

Video	imgsz 1024 (ms/frame)	imgsz 640 (ms/frame)
drone1.mp4		304 155
drone2.mp4	261 144

Although imgsz=1024 is better at detecting small or distant objects, imgsz=640 is much faster on the CPU (~6-7 FPS). Because speed is very important for the drone to fly in real-time, we accept a slight drop in accuracy and recommend setting IMGSZ=640.
